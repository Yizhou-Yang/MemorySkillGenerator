Root cause: fasttext 0.9.3 is installed and imports fine, but it's incompatible with NumPy 2.0. In `FastText.py` it calls `np.array(x, copy=False)` in three places (lines 41, 56, 239). Under NumPy 2.0, `np.array(obj, copy=False)` raises `ValueError: Unable to avoid copy while creating an array as requested` whenever a copy is actually needed — which is exactly what happens during `predict`. That's why basic functions (like `tokenize`) seemed to work but real usage failed.

Fix applied: I replaced the three `np.array(x, copy=False)` calls with `np.asarray(x)` in `/usr/local/lib/python3.13/site-packages/fasttext/FastText.py`:

```
sed -i -E 's/np\.array\(([^,]*), copy=False\)/np.asarray(\1)/g' /usr/local/lib/python3.13/site-packages/fasttext/FastText.py
```

This is the NumPy-recommended migration (`np.asarray` allows a copy when needed, no behavior change on NumPy 1.x either), so it's safe regardless of NumPy version.

Verified with the default `python` (3.13.1): training, saving, loading, predicting, and `get_words` all work now.
